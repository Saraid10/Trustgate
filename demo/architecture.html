TrustGate

authorization between an AI agent and a payment provider

1 · The trust boundary

The agent proposes three fields. Everything that decides what the money does is derived on the server. There is no amount field for injected text to fill.

Authorization and payment are separate steps. A purchase can sit AUTHORIZED indefinitely with order creation still refused, because no checkout authority has been issued. That gap is the product.

2 · The layers

Delete the agent entirely and everything below the second line is unchanged and still correct. If the agent were the centre of this, the project would be arguing against itself.

3 · Where each rule is enforced

One rule throughout: enforce at the lowest layer that can hold it. Database constraint over transaction, transaction over application code, application code over convention — because a rule in Python is a rule a different query walks around.
